# C-Play Version 2.4

This is the landing page for the documentation of C-Play Version 2.4, from the application itself. This version is currently in beta on a separate development branch; when it becomes the latest release, the continuously updated guides below apply to this release.

This update introduces NDI output — C-Play can now publish its main video and individual presentation layers as NDI sources that other applications (e.g. OBS Studio) can receive over the network. It also adds **streaming of layer textures from the master to the nodes** over UDP multicast or NDI, so a layer is rendered once on the master and shown frame-synced on every node without decoding it again; two new live input layer types with optional audio — **WebRTC** (WHEP streams, e.g. from MediaMTX) and **DirectShow** (Windows camera/capture card input or media files rendered through DirectShow); a dedicated **YouTube** layer type playing single video URLs as VOD content through yt-dlp; an optional [MediaMTX](https://github.com/bluenviron/mediamtx) integration for discovering available live streams, plus multi-video composition for nodes, master-only layers, and several 3D view improvements.

#### NDI output
C-Play v2.4 can send its own video out through NDI: in addition to the full player output, each presentation layer can be published as an independent NDI source from the master. The main output follows the [master view](/playback/views#-master-view) — while a 3D view mode is active it publishes the rendered 3D scene instead of the main video, at a selectable resolution (2K–8K). Video only for now. There is also an option to **show the master NDI output on all nodes**: when enabled, the nodes render the "C-Play" NDI stream from the master instead of their own layers (the NDI output has to be ON), which is handy for checking what a receiver such as OBS Studio sees. See [C-Play -> NDI output](/system-integration/ndi-output).

#### New live input layers: WebRTC and DirectShow
Two new layer types can be added in the *Add new layer* dialog of the presentation tool:

* **WebRTC** — pulls a WHEP stream over the network by URL, for example from [MediaMTX](https://github.com/bluenviron/mediamtx) or VDO.Ninja's hosted WHIP/WHEP service (see [VDO.Ninja -> C-Play](/system-integration/vdo-ninja)). Video (H.264/H.265) and audio (Opus) are decoded with FFmpeg, using NVDEC hardware decoding when available, and a failed session is re-established automatically while the layer should be running. By default the **master pulls the stream once and relays it to all nodes** over WebRTC data channels, so the upstream server only has to serve one connection; the *Master relay* option can be turned off per layer if every node should pull its own copy instead. Requires a build with WebRTC support (`BUILD_CPLAY_WITH_WEBRTC`, off by default).
* **DirectShow** — Windows only. Capture live from a camera or capture card chosen in the dialog (video and audio devices are listed separately), or render an image/video file through a DirectShow filter graph using the system's built-in decoders. Audio is optional: pick an audio device to route its audio to the machine's output, leave it empty for media files so their own audio track is used when available, or select *No audio capture* for a video-only layer that captures no audio at all (not even embedded card audio). Predefined capture setups can be stored in `data/predefined-directshows.json`. Enabled by default in Windows builds (`BUILD_CPLAY_WITH_DIRECTSHOW`).

See [Build presentation](/media/cplaypres) for how to add and configure both layer types.

#### Streaming layers from master to nodes
By default each node loads and decodes its own copy of every layer in a presentation. C-Play v2.4 can instead **stream the rendered texture of a layer from the master to all nodes**: the layer is rendered once on the master, block-compressed on the GPU (BC1/BC3/BC7) and sent over UDP multicast — or, when NDI support is built in, published as an NDI source received by automatically created NDI layers on the nodes. Per-layer options include compression format, frame-locked vs immediate sync, max frame rate, and group/port overrides; global defaults (base multicast group/port, send interface, TTL, datagram size, rate limit, latency guard) are in the [presentation settings](/settings/presentation#layer-streaming-to-nodes). This saves decoding resources on the nodes and keeps every node on exactly the same frame. See [Streaming layers from master to nodes](/playback/node-streaming).

#### YouTube layer
A new **YouTube** layer type plays a single YouTube video URL (watch, shorts or youtu.be) as video-on-demand content: it gets the full set of player controls — play/pause, seek slider, stop/rewind, end-of-file mode and A-B section looping — exactly like a Video layer. The URL is resolved by mpv's embedded `ytdl_hook` using the external [yt-dlp](https://github.com/yt-dlp/yt-dlp) tool, which every cluster machine needs available (the URL syncs verbatim and each machine resolves it locally). See [Layers and sources → YouTube playback and yt-dlp](/media/layers#youtube-playback-and-yt-dlp).

#### MediaMTX stream discovery
C-Play can connect to a [MediaMTX](https://github.com/bluenviron/mediamtx) server through its control API, list the streams it currently serves, and turn any of them into a **Stream** layer (RTSP or SRT URL) or — when the server has WebRTC enabled and C-Play was built with WebRTC support — a **WebRTC** layer pulling via WHEP. Servers are configured in *Settings -> MediaMTX Streams...*, and on Windows passwords can be kept out of the saved configuration through the Windows Credential Manager. See [MediaMTX streams](/system-integration/mediamtx).

#### Multi-video composition (*.cplaymulti)
Multiple videos can play simultaneously on cluster nodes, all time-synced to a single master reference video, with per-node file paths and different rendering mappings (e.g. left/right eye for stereoscopic domes). See [Multi-video composition](/media/cplaymulti).

#### Master-only layers
Layers in the layer view can now be marked to exist on the master only — not synced to the nodes — with a new **Sync** button. This is useful for example for layers whose purpose is NDI output, or control-only layers. A new user interface setting hides such layers from the 3D view by default. See [Window & UI](/settings/window_and_ui) and [C-Play -> NDI output](/system-integration/ndi-output#master-only-layers-sync-button).

#### 3D view improvements
Zoom in the dome render view, moving selected layers with Ctrl + left mouse click, and saving the camera position/rotation as startup values (double-clicking restores the saved pose). The header taskbar view-mode button is now a menu that selects how the master view renders: only the main video, all layers in a 3D view with a perspective camera, or all layers in a 3D view with a fisheye camera — a new optional **180° fisheye (fulldome) projection** that shows your dome/sphere content as a flat circular image. See [Views](/playback/views#fisheye-180-projection-fulldome) and [Window & UI](/settings/window_and_ui).

#### Other changes
* Optional framesync system for tighter synchronization between nodes.
* Per-file mpv options in playfiles, for example to select if a video should decode alpha or not.
* Optional guessing of grid mode when dragging media onto the layers list.
* Updated to OpenGL 4.6 and latest SGCT, with OpenXR support.
* Audio level meter in the layer view for live layers that report audio levels (NDI, OMT, DirectShow and WebRTC).
* New **Logging** window: toggle general application/MPV logging and enable MPV performance statistics with a live table of perf-info rates and frame drop counters.
* Option to set the default EOF mode on file load in the [playback settings](/settings/playback), for files without a saved EOF mode of their own.
* The global mute is now propagated to all layers, including live input layers.
* Predefined streams and DirectShow setups can resolve different local paths/devices per machine in a cluster (`data/predefined-streams.json`, `data/predefined-directshows.json`).
* Node window transparency: windowed node windows now use a transparent framebuffer by default (unrendered areas show the desktop), with a new **Node window opacity mode** setting to choose between *Complete window (uniform fade)* and *Content-based (fades background only)*, synced from the master to the nodes. See [Window & UI](/settings/window_and_ui).
